# Agent Creator（Agent 创造者）

## 定位

Agent Creator 是一类"元代理"（meta-agent）：它本身不直接完成业务任务，而是根据用户的具体需求以及项目（本仓库）的实际情况，设计、生成或推荐一个新的、专用的 Agent 配置。

## 职责

1. **理解意图**：分析用户描述，识别其想要构建的 Agent 需要完成什么功能、聚焦于哪个方向（例如：契约字段校验、契约文档生成、契约版本兼容性检查等）。
2. **结合项目实际情况**：本仓库（`zkaliagent/contracts`）以 `contracts.json` 描述"契约字段"（contract-field）的结构化定义（字段名称、类型、约束、默认值、引用关系等）。任何新 Agent 的设计都应尊重这一契约字段模型，确保生成的配置或产出物与现有字段定义（`fields` 下的 `name`、`type`、`required`、`enum` 等）保持兼容。
3. **产出符合意图的 Agent 设计**：包括但不限于：
   - Agent 的角色（Role）与职责边界
   - 输入 / 输出的定义（尽量复用 `contracts.json` 中已定义的字段类型体系）
   - 关键校验规则（如必填字段、枚举取值、正则匹配规则等）
   - 与现有 CI 校验（`.github/workflows/standard-ci.yml`，用于校验 `contracts.json` 的 JSON 语法与必填 key）的兼容性

## 设计原则

- **最小改动**：新 Agent 的设计应尽量复用现有契约字段类型体系，避免引入与本仓库模型冲突的新概念。
- **可校验**：产出的字段定义应能够被现有 CI（JSON 语法及必填 key 校验）正确解析和校验。
- **意图优先**：始终以准确理解并满足用户的具体功能诉求为第一优先级，而非套用固定模板。

## 使用场景示例

- 用户希望新增一个"契约版本"（contract-version）相关的字段定义 Agent。
- 用户希望有一个 Agent 专门检查 `contracts.json` 中字段的引用关系（`ref`）是否有效。
- 用户希望生成一个用于校验字段命名规范的 Agent。

> 说明：Agent 的具体运行时配置（面向其他自动化代理的指令文件）位于 `.github/agents/` 目录下，由项目维护者单独管理；本文档仅作为面向人类贡献者的说明性参考。
